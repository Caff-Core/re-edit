## ReUI design rules (every UI edit, follow-ups included)

This project uses an existing design system: ReUI on shadcn/ui. Keep its look. Generic frontend advice (vary fonts or themes, gradients, page-load or staggered reveals, "2-3 intentional motions", Framer Motion) does not apply here, and other design skills lose where they disagree.

1. Use installed components first (`components/ui`, `components/reui`): tables `data-grid`, filtering `filters`, boards `kanban`, modals `Dialog` or `AlertDialog`, toasts `sonner`. Never set height, radius, padding, shadow or motion on them; use `size`, `variant`, `spacing`.
2. Color: semantic tokens. State: `<Badge variant="success-light">` from `@/components/reui/badge` at default size, or Alert variants. Raw palette only for categorical identity, with its `dark:` pair.
3. Spacing: `gap-*` on the parent: `gap-1` to `gap-2` in a row, `gap-3` to `gap-4` between groups, `gap-6` to `gap-8` between sections. Type: `text-sm` body, `text-xs` meta, nothing smaller; never resize FrameTitle or CardTitle.
4. Motion: installed parts already animate; never retime them. Yours: hover `transition-colors`; reveal `duration-200 ease-[cubic-bezier(0.22,1,0.36,1)]`; transform and opacity only; never `transition-all`, bounce, or a stagger on table rows or lists of 20+; at most 1 entrance per view; `MotionConfig reducedMotion="user"` plus `motion-reduce:`.
5. Every data region: empty state with an action, `Skeleton` loading, inline error with Retry.
6. Before UI code, write the plan from `.agents/skills/reui/SKILL.md` in your reply. Before you finish, run its self-check on the files you changed and fix every hit (2 rounds at most). Full rules: `.agents/skills/reui/SKILL.md`. If that folder is missing, call the `reui` MCP tool `get_agent_skill`.

Managed by the ReUI installer. Edits between the markers are replaced on the next run.

## Project structure

Follow the atomic design rules in `docs/.specify/memory/constitution.md`. ESLint (`eslint.config.js`) and `src/components/structure.test.ts` enforce them.

```
src/
  app/                 Router setup, providers (theme), and app-level views (status, not found).
  routes/              TanStack Router file routes. routeTree.gen.ts is generated by Vite; commit it.
  components/
    ui/                shadcn/ui, installed by the CLI. Do not edit.
    reui/              ReUI, installed by the CLI. Do not edit.
    atoms/             Shared primitives that wrap or compose ui/ and reui/.
    molecules/         Atoms combined around a single interaction.
    organisms/         Sections such as the file tree and tab strip.
    templates/         Layouts such as the app shell.
  features/<name>/     Document features (markdown, ...). index.ts is the public API.
  services/native/     Typed boundary to the Tauri host. Mirrors src-tauri/src/native.
  lib/  hooks/         Shared, feature-neutral helpers.
  test/                Test setup and fixtures.
```

- A tier imports only lower tiers: templates > organisms > molecules > atoms > ui and reui.
- Shared components (`src/components/**`) never import a feature. Their props describe data and callbacks, not document types.
- Feature-specific components live in `src/features/<name>/components`, not in the shared tiers.
- Outside a feature, import it only through `@/features/<name>`. Inside a feature, use relative imports.
- Every file in `src/components` sits in a tier or vendor folder. Every feature has an `index.ts`.
- Native operations go through `src/services/native`. Never call `invoke` from components or features.
- Routing uses hash history so every route stays inside the one `index.html` Tauri serves. Give each route `staticData: { title }` for the shell header.
- A Base UI `Button` given `render={<Link />}` becomes `<a role="button">`. For navigation, style the `Link` with `buttonVariants()` so it stays a link.
- `SidebarProvider` toggles the sidebar on Ctrl/Cmd+B at the window. Editor keymaps that bind Mod-b must stop propagation.
